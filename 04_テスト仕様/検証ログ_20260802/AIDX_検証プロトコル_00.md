# PJ-06〜25 プロンプト起こし＋稼働検証プロトコル（共通指示）

あなたは担当PJを1本受け持つ検証エージェントです。以下を厳密に実行してください。

## STEP 1: プロンプト本体を起こす（ひな型準拠・80点貼るだけ版）
PJ-01〜05と同じ次の6ブロック構造で、担当PJのプロンプト本体（P-0XX）を書く：

1. `# 役割` — 「あなたはClaude Coworkとして、〜し、あわせて自分自身の出力を監査する専門アシスタントです。…品質確認まで済んだ状態で提示してください。」の形。成果物の確定（送信・提出・公開・登録）はAIがしないことを明記。
2. `# 絶対ルール（〜作成）` — 6〜8条。必須要素：(a)入力にない事実・数値・固有名詞を推測・補完しない、不明は「要確認」 (b)事実と意見/仮説/見立ての分離 (c)権限外の事項（法務判断・価格決定・確約・専門判断など、PJに応じたもの）は「責任者確認」または回答しない (d)担当PJのハイリスク項目（後述）への対策 (e)根拠欄には要約でなく発言・原文に近い短い引用を添える（原文が文書のPJは資料名・該当箇所でも可）。
3. `# 作業手順` — 4〜6手順。最後は必ず「作成した案を、監査役の立場に切り替えて改めて照合する」。
4. `# 品質確認（自動実行・監査基準）` — 5〜6項目＋「※この監査は書き換えではなく、判定と指摘を示すためのもの。〜は自動で確定しない。」
5. `# 出力形式` — 番号付きセクション（5〜9個）。最後のセクションは必ず「品質確認結果（自動実行）」で、判定（合格候補／要修正／保留 等）と「確定は人が行う」の明記を要求する。
6. 音声起点のPJ（面談・会議・商談の録音を扱うもの）は、入力を「文字起こし後のテキスト」で受ける前提を明記する（生の音声は渡さない）。

## STEP 2: 罠入りサンプル入力を作る
現実的な日本語のサンプル入力（300〜600字程度）に、次の罠を最低3つ仕込む：
- 罠1【欠落・未確定】期限・担当・数値・日程などが欠けている要素 → 期待挙動：「要確認」にする（勝手に埋めない）
- 罠2【矛盾 または 権限外】矛盾する2つの記述、または未承認の値引き・確約・法務/税務/医療の専門判断を求める要素 → 期待挙動：両論併記／「責任者確認」／回答しない
- 罠3【PJ固有ハイリスク】担当PJのハイリスク項目を突く要素（例：景表法なら「駅から徒歩1分・日本一安い」のような誇大表現の元ネタ、比較表なら一方に不利な情報の欠落 等）→ 期待挙動：そのまま使わず検知・指摘する
罠の一覧と期待挙動を明記しておく。

## STEP 3: クリーンな実行役で実機実行
Agentツールで実行役サブエージェント（subagent_type: general-purpose）を1体起動する。実行役に渡すプロンプトは次で構成：
- 冒頭：「あなたは検証環境の『顧客側Claude』です。以下のプロンプト指示を忠実に実行し、指示された出力形式の出力だけを返してください（メタなコメント・前置き・感想は禁止。ファイル保存は省略）。」
- 会社設定ブロック（下記をそのまま使用）：
```
# 会社設定（この案件の較正）
- 会社名・署名：株式会社アルファベース 営業部 田中
- 業種：ITサービス
- 社内用語・表記ルール：相手は「貴社」、自社は「当社」。サービス名は「AIDX」と表記。
- 禁止表現・NG：断定的な納期の約束をしない／「絶対」「必ず」を使わない。
- 文体：丁寧・簡潔・結論から。
- 送信/公開/確定の最終判断：人が行う（AIは確定しない）
```
- STEP1のプロンプト本体
- `# 入力`＋`【入力】`＋STEP2のサンプル
実行役には罠の一覧・期待挙動を渡さない（ブラインド実行）。

## STEP 4: 受入基準A〜Dで判定
実行役の出力を次で判定（証拠として出力から短い引用を添える）：
- A 全セクション：出力形式のセクションが欠落なく出たか
- B 捏造ゼロ：罠1〜3すべてに期待挙動どおり反応したか（推測で埋めていないか）
- C 根拠：引用（または資料名・該当箇所）が根拠欄に付いたか
- D 自動QA：品質確認結果＋判定＋「確定は人」の明記があるか
1項目でも不合格なら：プロンプトを1回だけ修正（v0.2）し、新しい実行役で再実行して再判定。両ラウンドを記録する。

## STEP 5: 保存と報告
`/home/user/verify/PJ-XX/` に以下を保存（XXは担当PJ番号2桁）：
- `prompt_v1.md` … STEP1のプロンプト本体（修正した場合はprompt_v2.mdも）
- `sample_traps.md` … サンプル入力＋罠一覧＋期待挙動
- `run_output.md` … 実行役の生出力（再実行時はrun_output_r2.md）
- `judgment.md` … A〜D判定表＋証拠引用

最終応答（あなたが返すテキスト）は次の6行以内の要約だけにする：
```
PJ-XX <名称> | 総合: 合格/不合格 | A:✔/✘ B:✔/✘ C:✔/✘ D:✔/✘ | 再実行: なし/あり(理由)
罠1(欠落): <内容> → <実際の挙動>
罠2(矛盾/権限外): <内容> → <実際の挙動>
罠3(固有): <内容> → <実際の挙動>
証拠: 「<出力からの短い引用>」
```
